# Honeyleaf — build plan

> A cozy scrapbook diary that lives on a desk. React + TypeScript on the front,
> plain PHP 8.2+ and MySQL/MariaDB on the back, deployable to any Hostinger
> shared plan by uploading one folder, importing one SQL file and filling in one
> config file.

This document restates the brief, records every assumption made where the
brief was open, and fixes the folder structure and save format before the real
build starts. It is updated at the end of each milestone.

---

## 1. The plan in one page

1. **Design first.** Build the default *honey-oak desk at golden hour* with the
   open journal and one fully decorated sample spread as a static screen.
   Screenshot it and get a yes on the look before wiring anything up. That
   screen is the visual bar for everything after it.
2. **Milestone 1 — the desk and the book.** Setup wizard, the journal-shaped
   login, the admin's key ring, the welcome letter, spreads with page turns,
   entries with date headers, text that flows across pages inside an adjustable
   writing area, 12 fonts, the inks and highlighter, 6 papers, instant-photo
   frames, 2 sticker packs, washi tape, move/rotate/resize/layers, unified
   undo/redo, autosave + IndexedDB safety net + offline queue, desk calendar and
   month tabs, trash, export/import, Hostinger packaging and the beginner
   README. Responsive from the start.
3. **Milestone 2 — make it gorgeous.** All six scenes, time-of-day light and
   seasons, the full font/ink/paper sets, lettering styles and text effects,
   free text boxes, stamps, paper things and envelopes, drawing tools, the full
   sticker library and the sticker maker, every photo frame and filter, covers
   and cover decorating, the prompt jar, desk life and sound.
4. **Milestone 3 — make it mine.** Multiple journals, rearranging the desk, the
   theme studio, custom fonts, templates, tags/moods/weather/favorites, search,
   table of contents, on this day, year in pixels, print and save-as-PNG,
   secret pages, installable offline PWA, mobile polish, a performance and
   accessibility pass.

Every milestone ends with `npm run build`, `npm test`, the PHP smoke test and a
deployable `upload/` folder, followed by a note on what works, how to try it
and known issues.

## 2. The five rules and how they are enforced

| Rule | How the code keeps it |
| --- | --- |
| **A desk, not a dashboard** | No layout chrome at all: the app is one scene. Every control is an SVG/CSS object or a piece of stationery. No UI kit is installed. A test scans the built CSS for system font stacks, `Inter`, `Roboto` and `system-ui`. |
| **Private and invite-only** | No sign-up page, link or endpoint exists. Every API route except `session`, `login` and the one-time setup requires a session; every query is scoped to the signed-in user (composite primary keys `(user_id, id)`); admin routes check the role. Photos are served only through an authenticated PHP endpoint. A strict CSP (`default-src 'self'`) plus a build check that greps `dist/` for any `http(s)://` URL to another domain. |
| **Hostinger shared hosting** | Static files + PHP 8.2 + MySQL/MariaDB only. No Composer, no Node on the server, no sockets, no daemons. Optional cleanup runs from hPanel cron. Migrations can run without SSH. |
| **Original art, free licenses** | All art (props, stickers, tapes, stamps, covers, textures, icons, the sample "photo") is drawn in SVG/CSS/canvas in this repo or generated by build scripts. Fonts come from Fontsource packages (OFL / Apache 2.0) and are copied with their license files. A script checks shipped runtime dependencies against an allowlist (MIT, ISC, Apache-2.0, OFL-1.1, CC0-1.0). |
| **Never lose a word** | Every edit lands in IndexedDB first, then syncs ~1 s after typing stops, on page turn and on leave. Offline edits queue and replay. Entries carry a version; a mismatch creates a conflict copy instead of overwriting. Every saved document carries a schema version with client migrations and server checks. One-click export. |

## 3. Assumptions and defaults (decided where the brief was open)

**Accounts & security**

1. The person who runs the setup wizard becomes the first admin. To stop a
   stranger from finding a fresh install first, the wizard asks for a
   **setup key** that you write into `config.php` (one extra line, explained in
   the README).
2. Sessions are stored in MySQL (not PHP's file sessions) so that "sign out
   everywhere", device lists and revocation work. The cookie holds a random
   256-bit token; the database holds only its SHA-256 hash. A new token is
   issued at every login. Cookies are `HttpOnly`, `Secure` (on HTTPS),
   `SameSite=Lax`, path-scoped to the install folder.
3. Without "remember this device", a session ends when the browser closes and
   expires server-side after 12 hours. With it, the cookie lasts 30 days.
4. **Locking is enforced on the server**, not just hidden in the browser: a
   locked session refuses every diary call until the password is entered again.
   Idle lock defaults to 15 minutes (adjustable in the drawer).
5. CSRF: a per-session token sent in an `X-Honeyleaf-CSRF` header on every
   state-changing request, checked with `hash_equals`.
6. Login rate limits (stored in MySQL): 5 failures per username and 30 per IP
   per 15 minutes, then a cooldown. Unknown usernames still run a password
   check against a dummy hash so timing never reveals whether a name exists.
7. Admin recovery: the admin can use the one-time recovery code on the login
   tag. If both are lost, the README explains putting a one-time
   `admin_reset_token` into `config.php`.
8. Secret pages use PBKDF2-SHA-256 (600 000 iterations) to derive an
   AES-GCM-256 key from the page passphrase in the browser. The server only
   ever sees ciphertext; sealed pages have no plain-text copy, so they are left
   out of search.
9. CSP: `script-src 'self'` (same-origin scripts only), `object-src 'none'`,
   `base-uri 'self'`, `frame-ancestors 'none'`, `connect-src 'self'`,
   `img-src 'self' blob: data:`, `font-src 'self' blob:`. `style-src` allows
   `'unsafe-inline'` because the rich-text editor writes ink colors and sizes as
   inline style attributes; scripts stay locked down.

**Hosting**

10. Upload layout: `upload/public_html/` (the app) and
    `upload/honeyleaf_private/` (config, PHP code, migrations, uploads). The PHP
    entry points look for `honeyleaf_private` next to `public_html` (and one
    level further up for subfolder installs). If the plan doesn't allow that,
    the folder can sit inside `public_html`, where its own `.htaccess` denies
    all web access.
11. **Base URL is detected automatically**: app routes go to a tiny
    `index.php` that serves the built `index.html` with the right
    `<base href>` for wherever it lives (domain root or `/diary/`).
    `config.php` can override it. No rebuild needed for a subfolder.
12. Database: InnoDB, `utf8mb4` with `utf8mb4_unicode_ci` (exists on both MySQL
    and MariaDB, unlike MySQL 8's default collation). Documents in
    `MEDIUMTEXT`, not the `JSON` type. Timestamps stored in UTC; entry dates as
    `DATE` in the writer's local calendar.
13. Migrations run automatically on the first API call after an update,
    guarded by a MySQL `GET_LOCK`, so beginners never need SSH. They are
    additive only. `schema.sql` always equals the latest state.

**Pages, text and drawing**

14. A page is **594 × 840 page units** (A5 at 4 units per mm). Text is laid out
    at that fixed size and the whole page is scaled with a transform, so line
    breaks and sticker positions are identical on every screen.
15. The ruled line grid is **28 units** (7 mm, close to college ruled), giving
    30 rows per page. Text that is bigger than one row takes a whole number of
    rows and is shifted so its baseline sits on a ruled line.
16. All fonts are normalized with `size-adjust`, `ascent-override` and
    `descent-override` computed at build time from each font's real metrics, so
    every family looks the same size and sits on the same baseline. The build
    fails if a font lacks á, é, í, ó, ú, ñ, ü or ç.
17. Text flow: each page stores its own share of the entry's text as TipTap
    JSON. When a page overflows, the flow engine splits the paragraph at the
    last line that fits and moves the rest to the next page (adding one if
    needed), marking the moved part as a continuation; deleting pulls text back
    and rejoins split paragraphs. Line breaks are identical everywhere for the
    same browser engine; across engines the stored page split keeps every word
    on its page.
18. One undo/redo history per open entry covers text and decorations together
    (the editors' own per-page history is switched off).
19. Selections don't span two pages in v1 (each page is its own editor);
    arrow keys, Backspace and Delete cross page boundaries naturally.
20. Decorations are clipped at the page edge, like tape trimmed with scissors.
21. IDs for journals, entries, pages and decorations are generated in the
    browser (sortable, 26 characters) so offline creation needs no round trip.
    The server scopes them per user, so a guessed or reused ID can never touch
    another person's data.

**Photos, export, sound**

22. Photos are resized in the browser with `createImageBitmap` (which applies
    EXIF orientation) to a 2 560 px long edge, re-encoded as WebP (JPEG where
    the browser can't encode WebP), which drops EXIF and GPS, plus a 480 px
    thumbnail. The server checks the real type with `finfo` and
    `getimagesize`, re-encodes with GD and stores files under random names in
    `honeyleaf_private/uploads/<user>/`.
23. Export is streamed by PHP as a `.zip` (pure-PHP streaming writer, so it
    needs neither `ZipArchive` nor much memory), optionally one year at a time.
    Import happens in the browser: the zip is read with `fflate` and replayed
    through the normal API piece by piece, so it never hits PHP upload or time
    limits and works on any fresh install.
24. Sound effects and ambience are synthesized with the Web Audio API at
    runtime, so there are no audio files to license. Ambience starts off;
    effects play quietly; one tap on the radio mutes everything.
25. The interface font is **Patrick Hand** (friendly, very legible
    hand-lettering); **Atkinson Hyperlegible** is offered in the drawer.

**Process**

26. Dependencies are pinned to exact versions (`save-exact`) and resolved with
    npm's `--before` date set two weeks back, to avoid brand-new releases.
27. Hostinger runs LiteSpeed; everything in `.htaccess` sticks to directives
    LiteSpeed and Apache both understand (no `php_flag`).
28. Local development uses Vite's dev server proxying `/api` to PHP's built-in
    server. PHP and MySQL/MariaDB are not installed on this machine yet; the
    README covers installing them (XAMPP is the easiest route on Windows).

## 4. Architecture

### Front end (`client/`)

- **`model/`: pure, framework-free TypeScript**, unit-tested with Vitest:
  page geometry and line grid, the text-flow engine (split/merge/reflow
  against a measuring interface), decoration types and transform math
  (rotate/scale/flip about the center, pinch and twist, snap to straight),
  unified history, save-format types and migrations, plain-text extraction.
- **`editor/`**: TipTap 3 with free extensions only, plus our own marks
  (`font`, `size`, `ink`, `highlight`, `effect`) and nodes (checklist items with
  hand-drawn boxes, bullet styles, doodle dividers, taped quotes). A DOM
  measurer feeds the flow engine.
- **`journal/`**: cover, spread, page view, page-edge thickness, ribbon, month
  tabs, the page turn (a 2-D fold that follows the dragged corner, with shading
  and a shadow on the page beneath, animated to finish or snap back).
- **`decor/`**: the decoration layer: one positioned element per decoration
  driven by Pointer Events, with our own handles. During a drag only the
  element's transform changes; the store is updated on release. Shadows are
  per-decoration with the offset counter-rotated so light always comes from
  the scene's light source.
- **`desk/`**: the scene, desk objects (each a real `<button>` with a label,
  a lift-and-wiggle hover, a paper name tag, and a hand-drawn focus ring), the
  lighting layers, desk life and the phone/tablet pencil-case tray.
- **`data/`**: TanStack Query for the API, Zustand stores for the editor and
  desk, IndexedDB (drafts + outbox) and the sync loop.
- **`library/`** (served from `public/library/`): JSON manifests and every
  swappable asset: fonts, textures, props, stickers, tapes, stamps, frames,
  covers, scenes, papers, inks, lettering, templates and prompts. Replacing a
  file or adding a manifest line changes the art without touching code.
- **`strings/en.ts`**: every word of interface text.

### Back end (`server/`)

- `public/index.php` serves the app shell with headers and the detected base
  URL; `public/api/index.php` is the single API front controller.
- `private/src/` holds plain PHP 8.2 classes: `Db` (PDO, prepared statements
  only, `SET time_zone = '+00:00'`), `Router`, `Session`, `Csrf`, `RateLimit`,
  `Auth`, `Validate`, `Images` (GD), `ZipStream`, and one controller per area:
  setup, auth, admin, journals, entries, assets, search, calendar, trash,
  settings, export.
- `private/cron/cleanup.php` empties trash older than 30 days, expired
  sessions and stale rate-limit rows. The app also does a light version of
  this opportunistically, so the cron job is optional.

### Data model

```
users ─┬─ sessions
       ├─ settings (one JSON document per person)
       ├─ journals ── entries ─┬─ pages (doc MEDIUMTEXT + plain_text, FULLTEXT)
       │                       └─ entry_tags
       └─ assets (photos, stickers, fonts; files outside the web root)
app_meta, migrations, rate_limits
```

Every user-owned table has the primary key `(user_id, id)` and every query
includes `user_id = :me`. Soft deletes (`deleted_at`) give the 30-day trash.

### Save format v1

```jsonc
// pages.doc
{
  "v": 1,
  "paper": { "id": "lined-cream" },
  "area":  { "top": 112, "right": 36, "bottom": 28, "left": 76 }, // page units
  "text":  { "type": "doc", "content": [ /* TipTap JSON; split paragraphs carry attrs.cont = true */ ] },
  "decorations": [
    { "id": "01J…", "type": "sticker", "asset": "autumn/maple-leaf",
      "x": 420, "y": 610, "w": 96, "h": 96,   // center + size, page units
      "rot": -8, "flipX": false, "z": 7, "layer": "front", "locked": false,
      "style": {} }
  ]
}
```

Decoration types: `sticker`, `tape` (two points + width), `photo` (asset +
frame + the picture's own shape + crop + filter + caption; the crop is the
point of the picture at the middle of the frame's window and how far it is
zoomed, so a photo can be rearranged or put in another frame at any time
without losing anything), `stamp` (asset + ink + seed for the patchy
print), `paper` (sticky note, index card, scrap, label, ticket, envelope with a
hidden note), `text` (free text box with TipTap JSON), `drawing` (strokes with
pressure), `doodle`. Entry-level fields (date, title, mood, weather, tags,
header style) live on the entry row; each row and document carries
`schema_version`.

## 6. Testing

- **Vitest** (model): text flow with a fake measurer (overflow split at line
  boundaries, rejoin on delete, continuation flags, no lost characters,
  reflow stability), save-format migrations, transform and gesture math,
  history, manifest validation (every file exists, content minimums are met).
- **Build checks**: font accent coverage, no external URLs in `dist/`, no
  forbidden fonts in CSS, first-load size budget (< 1.5 MB gzipped), license
  allowlist.
- **PHP smoke test** (`npm run test:api`, against its own throwaway database):
  setup → admin login → create a member → member changes temporary password →
  member cannot read the admin's entries or photos by ID → photo URL refused
  without a session → no sign-up route exists → conflict copies → trash →
  padlock → rate limit trips → export holds every page and photo → recovery
  code and reset token → cleanup. (Import runs in the browser, so it is
  checked there: export from one account, import into another, compare.)
