# Honeyleaf API contract (v1)

The single source of truth for the client (`client/src/data/`) and the PHP
back end (`server/`). Change this file first, then both sides.

## Conventions

- **Base path.** Every route lives under `<install>/api/`. The client calls
  `api/<route>` relative to the document base. Apache/LiteSpeed rewrites
  `api/<route>` to `api/index.php?r=<route>`; the PHP built-in dev server does
  the same through `server/dev-router.php`.
- **JSON** in and out (UTF-8), except uploads (`multipart/form-data`) and file
  downloads. Request bodies over 8 MB are refused with `413`.
- **Field names** are camelCase in JSON, snake_case in SQL.
- **Times** are ISO 8601 UTC strings (`2026-10-19T08:05:00Z`). **Dates** are
  calendar dates `YYYY-MM-DD` in the writer's own time zone (never shifted).
- **IDs.** Journals, entries, pages and assets use 26-character ULIDs in
  Crockford base32 (`^[0-9A-HJKMNP-TV-Z]{26}$`), generated by the client so
  things can be created offline. All of these are scoped per user: primary keys
  are `(user_id, id)`, so an ID can never reach another person's row. Users
  have integer IDs (admin screens only).
- **Session cookie** `hl_session`: random 256-bit token, `HttpOnly`,
  `SameSite=Lax`, `Secure` when the request is HTTPS, `Path` = install base.
  The database stores only `sha256(token)`. A remembered session gets
  `Max-Age` 30 days; otherwise the cookie is a browser-session cookie and the
  server expires it after `session_hours` (12) of idleness.
- **CSRF.** Every request except `GET`/`HEAD` must carry
  `X-Honeyleaf-CSRF: <token>`. `GET session` always returns the current token.
  Signed in: the token is stored on the session row. Signed out: the token is
  `HMAC-SHA256(app_secret, value of the HttpOnly cookie hl_anon)`; the server
  sets `hl_anon` on `GET session` when missing. Compared with `hash_equals`.
  The `setup/*` routes take the setup key from `config.php` instead (no one
  else knows it), and `GET session` answers `"csrf": ""` while in setup.
- **Errors.** Non-2xx responses have the body
  `{"error": {"code": "…", "message": "…", "fields"?: {…}, "retryAfter"?: seconds}}`.
  The client shows its own friendly text per `code`; `message` is for logs.

| HTTP | code | when |
| --- | --- | --- |
| 400 | `bad_request` | malformed JSON, missing fields |
| 400 | `validation` | `fields` maps field → reason (`required`, `too_long`, `invalid`, `taken`, `weak`) |
| 401 | `unauthenticated` | no or expired session |
| 401 | `invalid_credentials` | wrong username or password (never says which) |
| 403 | `forbidden` | not allowed (not admin, not yours) |
| 403 | `csrf` | missing or wrong CSRF token |
| 403 | `must_change_password` | temporary password still in use; only `session`, `auth/password`, `auth/logout` allowed |
| 403 | `setup_done` | setup endpoints after setup finished |
| 403 | `bad_setup_key` | wrong setup key |
| 404 | `not_found` | missing or someone else's |
| 409 | `conflict` | entry version mismatch (see `PUT entries/{id}`) |
| 413 | `too_large` | body, file or document too big |
| 413 | `storage_full` | the person's storage limit would be exceeded |
| 415 | `unsupported_type` | upload is not an allowed type by content |
| 423 | `locked` | the diary is locked; only `session`, `auth/unlock`, `auth/logout` allowed |
| 429 | `rate_limited` | with `retryAfter` |
| 503 | `setup_required` | no admin exists yet |
| 503 | `db_unavailable` | can't reach the database |
| 500 | `server_error` | anything else (details only in the PHP error log) |

## Session, setup and health

### `GET health`
No auth. `{"ok": true, "version": "0.2.0"}`.

### `GET session`
No auth. Always 200.
```json
{
  "state": "setup" | "signed_out" | "locked" | "signed_in",
  "csrf": "…",
  "user": { "id": 1, "username": "eddie", "displayName": "Eddie", "role": "admin",
            "mustChangePassword": false, "lockMinutes": 15 },   // omitted unless locked/signed_in
  "server": { "version": "0.2.0", "maxUploadBytes": 15728640, "trashDays": 30 }
}
```
Reading `session` does not count as activity for the idle lock. If the session
has been idle longer than the user's `lockMinutes`, it becomes `locked`.

### `GET setup/check`
Only while no admin exists (else `403 setup_done`). Tells the wizard what to fix.
```json
{
  "php": { "version": "8.3.35", "ok": true },
  "extensions": [ { "name": "pdo_mysql", "ok": true, "required": true }, … ],   // pdo_mysql, gd (+webp), fileinfo, mbstring, json, openssl, zlib, sodium (optional)
  "privateDir": { "outsideWebRoot": true, "writable": true },
  "uploads": { "writable": true },
  "https": true,
  "config": { "found": true, "setupKeySet": true },
  "db": { "connected": true, "tablesReady": false, "error": null }
}
```

### `POST setup/install-schema` `{setupKey}`
Creates the tables from `schema.sql` when they don't exist yet (a convenience
for people who skip phpMyAdmin). `{ "ok": true }`.

### `POST setup/admin` `{setupKey, username, displayName, password}`
Creates the first admin and closes setup for good. Returns
`{ "recoveryCode": "XXXX-XXXX-XXXX-XXXX" }` exactly once. Username:
3–32 characters `[a-z0-9._-]` (stored as typed, matched case-insensitively).
Password: at least 10 characters.

## Auth

### `POST auth/login` `{username, password, remember}`
200 → `{ "user": {…}, "csrf": "…" }` and a new session cookie (the token is
always new: session IDs are regenerated at login). Wrong username or password
→ `401 invalid_credentials` after the same amount of work. Turned-off account
→ same `401`. Limits: 5 failures per username and 30 per IP in 15 minutes →
`429` with `retryAfter`.

### `POST auth/logout`
Ends the current session. 200 `{}`.

### `POST auth/lock`
Locks the current session now. 200 `{}`.

### `POST auth/unlock` `{password}`
200 `{ "csrf": "…" }`. 5 failures in 15 minutes end the session (`401 unauthenticated`).

### `POST auth/password` `{current, next}`
Changes your password and clears `mustChangePassword`. Other sessions of the
same person are signed out. 200 `{ "user": {…} }`.

### `POST auth/recover` `{username, recoveryCode, next}`
Admins only: uses the one-time recovery code to set a new password. Returns a
fresh code `{ "recoveryCode": "…" }`. Same error and rate-limit behavior as login.
The `admin_reset_token` from `config.php` is also accepted as `recoveryCode`
(once per token value), so the emergency reset needs no extra screen.

### `POST auth/reset-token` `{token, username, next}`
Emergency admin reset with the one-time `admin_reset_token` from `config.php`
(see README). Works once per token value; returns `{ "recoveryCode": "…" }`.

### `GET auth/sessions`
`{ "sessions": [ { "id": "public16chars", "createdAt", "lastSeenAt", "remember": true, "current": true, "device": "Firefox on Windows" } ] }`

### `DELETE auth/sessions/{id}`
Revokes one of your own sessions. 200 `{}`.

## Admin (role `admin`; every route checks it)

Admins see names, roles, last sign-in and storage. They can never read anyone's diary.

- `GET admin/users` → `{ "users": [ { "id", "username", "displayName", "role", "active", "mustChangePassword", "lastLoginAt", "storageUsedBytes", "storageLimitBytes", "createdAt" } ] }`
- `POST admin/users` `{username, displayName, password}` → 201 `{ "user": {…} }`. The password is temporary (`mustChangePassword = true`).
- `PATCH admin/users/{id}` `{displayName?, active?, role?, storageLimitBytes?}` → `{ "user": {…} }`. `storageLimitBytes: null` removes the limit. Turning someone off signs them out. You can't turn yourself off or remove the last admin.
- `POST admin/users/{id}/password` `{password}` → sets a new temporary password and signs them out everywhere. `{ "user": {…} }`
- `POST admin/users/{id}/signout` → signs them out everywhere. `{}`
- `DELETE admin/users/{id}` `{confirm}` (must equal their username) → deletes the account, every row and every stored file. Not yourself. `{}`

## Journals

- `GET journals` → `{ "journals": [ { "id", "title", "cover": {…}, "defaults": {…}, "sortOrder", "createdAt", "updatedAt" } ] }`
- `PUT journals/{id}` `{title, cover, defaults, sortOrder}` → creates or updates. `{ "journal": {…} }`
- `DELETE journals/{id}` → to the trash with all its entries.

`cover` and `defaults` are JSON objects (max 64 KB each), stored as text.
`defaults` = `{ "paper": "lined-cream", "font": "caveat", "size": 22, "ink": "brown-black" }`.

## Entries

### `GET journals/{id}/entries`
The light index used for page numbering, the calendar and month tabs.
```json
{ "entries": [ { "id", "date": "2026-10-18", "title", "pageCount": 2, "pageIds": ["…","…"],
                 "version": 7, "hasPhotos": true, "conflictOf": null, "createdAt", "updatedAt" } ] }
```
Ordered by `date`, then `createdAt`. Trashed entries are left out.

### `GET entries/{id}`
```json
{
  "entry": { "id", "journalId", "date", "title", "header": {…}, "version": 7, "schema": 1,
             "conflictOf": null, "createdAt", "updatedAt" },
  "pages": [ { "id", "index": 0, "doc": { "v": 1, … }, "favorite": false } ]
}
```

### `PUT entries/{id}`
Saves a whole entry atomically (create or update).
```json
{
  "baseVersion": 7,            // null when creating
  "entry": { "journalId", "date", "title", "header": {…}, "schema": 1 },
  "pages": [ { "id", "index": 0, "doc": {…} } ]
}
```
- 200 → `{ "version": 8, "updatedAt": "…" }`.
- Pages that exist on the server but are missing from `pages` move to the trash,
  except pages the text flow added by itself (`doc.flow = "auto"`, no
  decorations): their words already moved to the pages around them, so they
  are simply removed.
- Version check: if the stored version differs from `baseVersion` (or the
  entry exists and `baseVersion` is null), nothing is overwritten. The server
  stores the incoming entry as a **conflict copy** (new ID, `conflictOf` =
  this ID, title `"<title> (copy from another device)"`) and answers
  `409 conflict` with `{ "error": {…}, "conflictCopyId": "…", "current": <same shape as GET entries/{id}> }`.
- Limits: 300 pages, 2 MB per page document, 8 MB per request, `schema` ≤ the
  newest the server knows (else `400 validation`).
- The server derives `pages.plain_text` (for search) and `entries.has_photos`
  from the documents itself; it never trusts client copies of them.

### `DELETE entries/{id}`
Moves the entry and its pages to the trash. `{}`

## Assets (photos, custom stickers, custom fonts)

### `POST assets` (multipart)
Fields: `id` (client ULID), `kind` (`photo` | `sticker` | `font`), `file`,
`thumb` (photos only, optional). Checks the real type from the bytes
(`finfo` + `getimagesize`), never the extension or the browser's claim.
Images are re-encoded with GD (WebP when available, else JPEG; PNG/WebP with
alpha for stickers), which also drops all metadata. Photos: at most 2 560 px on
the long edge (bigger ones are scaled down), thumbnails 480 px. Fonts: WOFF2,
TTF or OTF by magic bytes, at most 5 MB, stored as is. Files go to
`uploads/<userId>/<random 32 hex>` outside the web root. Limits: 300 uploads
per 10 minutes per person (imports send many photos), `max_upload_bytes` per file, the person's storage limit.
201 → `{ "asset": { "id", "kind", "mime", "width", "height", "bytes", "createdAt" } }`.
Re-sending an ID that already exists for this person returns the stored asset (idempotent retries).

### `GET assets?kind=photo`
`{ "assets": [ … ] }`, newest first.

### `GET assets/{id}?size=thumb|full`
The file itself, only for its owner (also while it is in the trash, so pages
that still show it keep working until it is emptied). Headers: the stored `Content-Type`,
`Cache-Control: private, max-age=31536000, immutable`, an `ETag`,
`X-Content-Type-Options: nosniff`, `Content-Disposition: inline`. Anyone else
(or no session) gets `404`/`401` with no file.

### `DELETE assets/{id}` → to the trash. `{}`

## Trash

- `GET trash` → `{ "items": [ { "type": "journal" | "entry" | "page" | "asset", "id", "label", "date"?, "entryId"?, "deletedAt", "purgeAt" } ] }`
- `POST trash/restore` `{type, id}` → `{}`. A restored page goes back to the end of its entry (and bumps the entry's version); a page whose entry is gone comes back as a new single-page entry.
- `POST trash/purge` `{type, id}` → deletes it for good (files too). `{}`

Anything in the trash longer than `trash_days` (30) is deleted by
`cron/cleanup.php`, and opportunistically by the API at most once an hour.

## Settings

- `GET settings` → `{ "settings": { … } }` (empty object for new people)
- `PUT settings` `{settings}` → stores the whole object (max 256 KB). If it
  contains `lockMinutes` (1–240), the server also uses it for idle locking.

## Export

### `GET export?year=2026`
Streams `honeyleaf-<username>-<date>.zip` (stored, not compressed, for photos;
deflated JSON). Without `year` it exports everything. Contents:
- `honeyleaf-export.json` — `{ "format": 1, "exportedAt", "app": "Honeyleaf 0.2.0", "journals": [...], "entries": [ { ...entry, "pages": [...] } ], "assets": [ { "id", "kind", "mime", "width", "height", "file": "assets/<id>.<ext>", "thumb"?: "assets/<id>.thumb.<ext>" } ], "settings": {…} }`
- `assets/…` — every stored file.

Import happens in the browser: the client reads the zip and replays it through
`PUT journals`, `POST assets` and `PUT entries` with fresh IDs, so it works on
any install and never meets PHP's upload or time limits.

## Database (schema 1)

`server/schema.sql` creates, in order: `app_meta`, `migrations`, `users`,
`sessions`, `rate_limits`, `journals`, `entries`, `pages` (with
`FULLTEXT(plain_text)`), `entry_tags`, `assets`, `settings`. InnoDB,
`utf8mb4` / `utf8mb4_unicode_ci`, documents in `MEDIUMTEXT`, timestamps in
`DATETIME` holding UTC (`SET time_zone = '+00:00'` on connect). Every
user-owned table has `PRIMARY KEY (user_id, id)` and a foreign key to `users`
with `ON DELETE CASCADE`.
